# Перенос на постоянно работающий VPS

Цель: `https://assistant.blackmindworks.com` работает на том же VPS, что `mrp` и `dashboard`, независимо от Windows-ПК. Эти два сайта и их конфигурация nginx не изменяются.

## До переключения DNS

1. Получить доступ по SSH к VPS и проверить память, свободный диск, Docker/Compose, nginx и существующие виртуальные хосты. Не выбирать порт, который уже занят; для этого проекта использовать `WB_WEB_PORT=3100` и при необходимости другой `WB_API_PORT`.
2. Создать на VPS отдельный каталог приложения и каталог секретов с правами только владельца. В `.env` задать случайный `POSTGRES_PASSWORD`, `WB_DOCKER_SECRET_PATH` (абсолютный путь к файлу Fernet-ключа), `WB_WEB_PORT=3100`, `WB_API_PORT=8100`, `WB_PUBLIC_ORIGIN=https://assistant.blackmindworks.com`. Секреты не записывать в Git.
3. Остановить локальное приложение на Windows и сделать согласованный снимок SQLite через `sqlite3.Connection.backup()`. **Не использовать переносимый экспорт из интерфейса**: он намеренно удаляет учётные записи и токены. Исходную базу не удалять. Перед передачей снимка убедиться, что `PRAGMA quick_check` возвращает `ok`.
4. Передать копию базы на VPS по SSH. Создать схему PostgreSQL через `docker compose run --rm backend python -m alembic upgrade head`. Начальная миграция создаёт служебный профиль `owner`; удалить его только в ещё пустой базе, если импортёр сообщает, что `store_profiles` уже заполнена. Импортировать данные командой `docker compose run --rm --user 0 -v /путь/к/копии.db:/tmp/source.db:ro backend python migrate_to_postgres.py /tmp/source.db` при условии, что на сервере уже задан `DATABASE_URL` контейнера. Импорт сохраняет сотрудников, товары, отзывы, вопросы, черновики и настройки, но исключает Windows DPAPI-токены, активные сессии и незавершённые задания. Он принудительно включает безопасный и тестовый режимы.
5. Дать backend-пользователю UID 10001 доступ на чтение Fernet-ключа: у файла на сервере владелец `10001:10001` и права `0400`, каталог `/etc/wb-ai-assistant` остаётся закрытым для остальных. Запустить `docker compose up -d --build`, загрузить модель `docker compose exec ollama ollama pull qwen3:4b` и проверить `http://127.0.0.1:3100/api/health` на VPS. При наличии голосовых моделей перенести их в volume `/data/models` и дать владельца UID 10001. Если памяти для Ollama не хватает, сначала подобрать серверные ресурсы; не заменять её внешним AI без отдельного решения владельца.
6. Создать **новый** nginx-сайт только для `assistant.blackmindworks.com` по шаблону `deploy/nginx-assistant.conf`, проксирующий на `127.0.0.1:3100`. Проверить `nginx -t`. После обновления DNS выпустить действительный TLS-сертификат через Certbot. Проверить вход сотрудников, количество отзывов и черновиков, генерацию ответа, вопросы и получение данных маркетплейса через HTTPS. Токены DPAPI нельзя перенести как есть, но их можно однократно расшифровать под исходной Windows-учётной записью и перешифровать серверным Fernet-ключом скриптами `deploy/rekey_windows_tokens.py` и `deploy/import_rekeyed_tokens.py`; не показывать значения в журналах и удалить временные файлы сразу после проверки. Альтернатива — ввести API-ключи заново в настройках владельца.
7. В Cloudflare заменить только DNS-запись `assistant` на A-запись VPS. Записи `mrp`, `dashboard` и остальные не менять. Проверить новый домен с другого устройства и после выключения Windows-ПК.

Пока SSH-доступ не получен и серверный сайт не проверен, DNS-запись менять нельзя: это немедленно отключит текущий адрес. После переноса установить `deploy/backup-vps.sh` и systemd-таймер из `deploy/`; копировать базу, `/data`, `.env` и Fernet-ключ с правами только root. Проверять копию через восстановление в отдельную временную базу. Копии на том же VPS защищают от ошибок в базе, но для защиты от потери самого VPS нужен отдельный внешний архив или снимок у провайдера.
