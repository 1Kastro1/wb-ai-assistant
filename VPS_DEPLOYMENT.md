# Перенос на постоянно работающий VPS

Цель: `https://assistant.blackmindworks.com` работает на том же VPS, что `mrp` и `dashboard`, независимо от Windows-ПК. Эти два сайта и их конфигурация nginx не изменяются.

## До переключения DNS

1. Получить доступ по SSH к VPS и проверить память, свободный диск, Docker/Compose, nginx и существующие виртуальные хосты. Не выбирать порт, который уже занят; для этого проекта использовать `WB_WEB_PORT=3100` и при необходимости другой `WB_API_PORT`.
2. Создать на VPS отдельный каталог приложения и каталог секретов с правами только владельца. В `.env` задать случайный `POSTGRES_PASSWORD`, `WB_DOCKER_SECRET_PATH` (абсолютный путь к файлу Fernet-ключа), `WB_WEB_PORT=3100`, `WB_API_PORT=8100`, `WB_PUBLIC_ORIGIN=https://assistant.blackmindworks.com`. Секреты не записывать в Git.
3. Остановить локальное приложение на Windows и сделать последнюю согласованную копию SQLite штатным механизмом резервного копирования. Исходную базу и её резервную копию не удалять. Перед передачей файла убедиться, что `PRAGMA quick_check` возвращает `ok`.
4. Передать копию базы на VPS по SSH. Создать пустую схему PostgreSQL через `docker compose run --rm backend python -m alembic upgrade head`. Затем импортировать данные командой `docker compose run --rm -v /путь/к/копии.db:/tmp/source.db:ro backend python migrate_to_postgres.py /tmp/source.db` при условии, что на сервере уже задан `DATABASE_URL` контейнера. Импорт сохраняет сотрудников, товары, отзывы, вопросы, черновики и настройки, но исключает Windows DPAPI-токены, активные сессии и незавершённые задания. Он принудительно включает безопасный и тестовый режимы.
5. Запустить `docker compose up -d --build`, загрузить модель `docker compose exec ollama ollama pull qwen3:4b` и проверить `http://127.0.0.1:3100/api/health` на VPS. Если памяти для Ollama не хватает, сначала подобрать серверные ресурсы; не заменять её внешним AI без отдельного решения владельца.
6. Создать **новый** nginx-сайт только для `assistant.blackmindworks.com`, проксирующий на `127.0.0.1:3100`, с заголовками `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`. Выпустить действительный TLS-сертификат. Проверить вход сотрудников, количество отзывов и черновиков, генерацию ответа, вопросы и получение данных маркетплейса через HTTPS. На VPS заново ввести API-ключи маркетплейсов один раз в настройках владельца: Windows DPAPI-токены переносить нельзя.
7. После успешных проверок заменить в Cloudflare только DNS-запись `assistant` (сейчас CNAME на `e30e10b0-54ad-461c-ae48-3e0f5dda924f.cfargotunnel.com`) на A-запись VPS `45.151.102.127`. Записи `mrp`, `dashboard` и остальные не менять. Проверить новый домен с другого устройства и после выключения Windows-ПК.

Пока SSH-доступ не получен и серверный сайт не проверен, DNS-запись менять нельзя: это немедленно отключит текущий адрес. После переноса настроить резервные копии PostgreSQL и каталога `/data` на VPS с проверкой восстановления.
