# Sequential review library audit

Stop the queue consumer before activation. Run `python -m app.review_library_audit --start` in the backend container, then restart the worker. Activation pauses imports, generation and publication, enables safe mode, cancels old jobs preserving checkpoints, converts the legacy library transactionally, and creates one durable sequential job: Yandex, Wildberries, Ozon. `/review-library/status` (owner only) and the Rules screen expose per-market progress. The maintenance flag stays on after completion; resume automation only on an explicit owner request.

Saved and published reply text is never rewritten. Only missing unpublished drafts use the ordinary generation pipeline. Timeouts preserve the cursor and retry after 1/2/5 minutes; configuration errors block the current market. Policy changes stop the campaign with a visible reason. Failed checks never produce approved templates. Replays preserve counters and deduplicate bodies. Final checks exercise actual retrieval per market, reject changed-policy reuse and confirm publication remains disabled. No-approved-reply stages are explicitly reported, not claimed as successful template tests.

One normalized body is shared across markets, with exact approved presentation preserved separately. Approval remains specific to rules, facts, review, rating, store and product. Only equivalent audited praise can reuse group approval. Similar complaints provide examples and require a fresh full check. Manual/risky references cannot confer automatic approval. New contexts have no cache-size eviction or age expiry; legacy expiration is retained during conversion. Changed rules/facts invalidate reuse through the context key.
