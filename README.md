# WB AI Assistant

Локальный помощник владельца магазина: чат на русском, отзывы, черновики, подтверждения, память и проверка применяемости по импортированному каталогу. Next.js + FastAPI + SQLite + Ollama. Обязательной подписки или платного AI API нет.

## Установка и запуск в Windows

1. Установите Python 3.12+, Node.js 22 LTS и [Ollama](https://ollama.com/download/windows). Если проект запускается на этом компьютере через Codex, скрипты также находят его комплектные Python/Node.
2. В Ollama скачайте модель: `ollama pull qwen3:4b`. Модель уже обнаружена на компьютере при разработке. Смена модели: скопируйте `.env.example` в `.env` и измените `OLLAMA_MODEL`.
3. Запустите `install.bat`. Он установит зависимости, скачает локальные голосовые модели, соберёт frontend и применит миграции.
4. Запустите `start.bat`. Откроется [локальное приложение](http://127.0.0.1:3000). При первом входе страница предложит создать пароль владельца длиной от 12 символов. После сохранения пароль хранится только как Argon2-хеш.
5. Остановка: `stop.bat`. Если зависимости уже установлены, создать первый пароль отдельно можно через `setup.bat`.

Скрипты запускают процессы скрыто, привязывают их только к `127.0.0.1` и сохраняют PID с временем запуска. Они не завершают посторонние процессы на занятых портах. Backend: порт 8000, frontend: 3000. Ошибки запуска: `%LOCALAPPDATA%\WBAIAssistant\data\run`. `setup.bat` оставлен как запасной консольный способ создания первого пароля.

## Данные и приватность

Код проекта может лежать в OneDrive. Рабочие данные туда не пишутся: по умолчанию используются `%LOCALAPPDATA%\WBAIAssistant\data\database\wb_assistant.db` и соседние каталоги. Используется профиль Windows текущего пользователя. Рекомендуется BitLocker для защиты диска. SQLite целиком не зашифрована.

LOCAL FIRST означает: AI работает в локальном Ollama, а backend обращается только к явно заданным API WB и к поиску DuckDuckGo, когда в карточке товара нет нужной инструкции по применению. В поисковый запрос передаются только публичные название и бренд товара; токен WB, текст отзыва и данные покупателя не передаются. Backend разрешает только фиксированные пары «провайдер / операция / URL», игнорирует системные HTTP-прокси и не следует перенаправлениям. Произвольных URL, shell и доступа к секретам у AI нет. Встроенный браузер не загружает внешние изображения, шрифты или аналитику. Облачного AI fallback нет.

WB Token защищён Windows DPAPI, привязан к учётной записи Windows; токен не возвращается API, не включается в AI-контекст и журналы. Пароль: Argon2. Сессия: HttpOnly/SameSite cookie, CSRF-проверки, ограничение попыток входа. Не запускайте с публичным bind и не публикуйте папку данных через веб-сервер.

## Подключение Wildberries

В «Настройки» введите токен с доступом к товарам и отзывам, сохраните и проверьте соединение. Затем синхронизируйте товары и отзывы. Повторный sync обновляет записи без дубликатов. Для нескольких кабинетов создайте отдельные профили магазина. У каждого профиля свой зашифрованный WB-токен, отзывы, история ответов, изученный стиль и отчёт качества.

Методы WB сверены с официальными материалами: [работа с товарами](https://dev.wildberries.ru/openapi/work-with-products), [общение с покупателями](https://dev.wildberries.ru/openapi/user-communication), [описание ответов на отзывы](https://dev.wildberries.ru/news/278). Доступ, тарифные ограничения и права токена зависят от WB. Наличие токена не гарантирует доступ к каждому методу.

## Обычный сценарий

Напишите «Покажи пять негативных отзывов», затем «Ответь на первые два». Черновики доступны в «Отзывы», где можно изменить текст. «Публикуй» создаёт ожидающее действие. В «Действия» видны точные тексты, версии, оценки, исключённые отзывы и режим. Изменение черновика делает прежнее подтверждение недействительным. Подтверждение действует 30 минут.

Кнопка «Подготовить ответы на все» сначала показывает объём работы, число быстрых и AI-ответов и примерное время, затем создаёт фоновое задание для всех отзывов активного магазина, которые ещё не имеют ответа или черновика. Ход работы, отмена и повтор находятся в «Очереди». Фильтр «Требуют внимания» собирает низкие оценки, опасные случаи и отзывы, для которых нужна ручная проверка. Это действие только готовит черновики: массовая публикация остаётся отдельным подтверждаемым шагом. Оценки 1–3 и опасные отзывы проверяют и подтверждают по одному. SAFE MODE блокирует публикацию в backend. TEST MODE по умолчанию включён: полный процесс подтверждения выполняется, но запрос записи WB не отправляется, отзыв не помечается реально опубликованным.

Автоответы обрабатывают только свежее окно отзывов — по умолчанию последние 7 дней, от 1 до 90 дней в настройках. Это защищает от случайного запуска генерации по всей старой истории магазина. Страница «Сегодня» показывает свежесть синхронизации, состояние планировщика, активные задания и размер базы. Конкретные ошибки отдельных отзывов доступны в «Очереди».

Для реальной публикации требуется отдельное решение владельца: после проверки тестового процесса добавить в `.env` `WB_ENABLE_REAL_PUBLISH=I_EXPLICITLY_AUTHORIZE_REAL_PUBLISH`, перезапустить и выключить TEST MODE в «Безопасность». В ходе разработки реальная публикация не разрешалась и не выполнялась. При сетевой неопределённости повторная отправка запрещена; сначала сверяйте фактический ответ в кабинете WB. Exactly-once на стороне WB без серверного idempotency key не гарантируется.

Правила EIKOSHA и опасных симптомов реализованы в коде отдельно от модели. Жалоба на скрип получает CAUTION, опасные симптомы — HIGH и ручную проверку. Шаблоны не ставят диагноз. Правило «Запомни…» требует отдельного подтверждения; можно выбрать global, product:ID, brand:Название или category:Категория.

## Голосовой разговор

В чате нажмите кнопку микрофона, разрешите браузеру доступ, произнесите запрос и нажмите кнопку остановки. Запись преобразуется в WAV и передаётся только локальному backend: русская модель Vosk распознаёт текст, после чего запрос обрабатывает обычный ассистент. Кнопка динамика включает автоматическое озвучивание каждого нового ответа через локальную модель Silero TTS; рядом с уже полученными сообщениями есть отдельная кнопка «Озвучить».

Silero и Vosk работают без облачной передачи аудио. Модели хранятся в `%LOCALAPPDATA%\WBAIAssistant\data\models` и устанавливаются командами `install.bat` или `update.bat`. Для голоса нужны исправный микрофон и разрешение сайта `127.0.0.1`. Первая генерация речи после запуска может занять несколько секунд, пока модель загружается в память.

## Каталог, VIN и OE

Импорт находится в «Настройки». CSV (UTF-8, запятая или точка с запятой), JSON (массив объектов), XLSX (первый лист, первая строка — названия колонок). До 10 МБ / 10 000 строк. Образец `examples/catalog.csv` содержит вымышленные учебные значения и непригоден для реального подбора.

Обязательны `brand`, `part_number`. Для подтверждённой применяемости нужны `make`, `model`, `generation`, `engine_code`, `year_from`, `year_to`, `axle`. Дополнительно: `engine`, `brake_system`, `disc_diameter`, `disc_thickness`, `pr_code`, `market`, `body`, `drive`, `production_date_from`, `production_date_to`, `vin_range`, `notes`, `category`, `wb_nm_id`. OE в `oe_number`, кроссы в `cross_number`; несколько номеров разделяются `|`. Номер продавца не считается автоматически артикулом производителя. Кроссы сохраняются, но сами по себе не доказывают применяемость.

Подтверждение источника — ручное заявление владельца после проверки документа. Импорт сам по себе не делает данные достоверными. OE нормализуется без пробелов/дефисов, но не служит достаточным доказательством совместимости.

VIN проверяется кодом: 17 символов, исключены I/O/Q. Без подключённого лицензированного источника автоматическая расшифровка произвольного VIN не обещается: используется локальное сопоставление с ранее сохранённым подтверждённым профилем. Для нового VIN введите профиль из проверенного источника и свяжите его с VIN. Хранятся солёный хеш и маска; полный VIN не сохраняется и удаляется из текстов отзывов перед записью. Проверка формата не подтверждает подлинность VIN.

Статусы: VERIFIED_FIT — точное соответствие подтверждённой записи; VERIFIED_NOT_FIT — не подходит; CONDITIONAL_FIT — условия не проверены; INSUFFICIENT_DATA — не хватает данных; CATALOG_CONFLICT — источники противоречат друг другу. Свободные ограничения из notes не теряются и блокируют безусловную рекомендацию. Только VERIFIED_FIT + товар WB в ассортименте + тот же или разрешённый бренд допускает автоматическую рекомендацию. Панель доказательств показывает все источники и условия.

## Резервирование и обновление

`backup.bat` либо кнопка в «Безопасность» создаёт согласованную SQLite-копию в локальной папке backups. Копия очищена от WB Token, хеша пароля и сессий; данные магазина остаются конфиденциальными. Не выкладывайте копии в публичный доступ.

Для переноса на другой компьютер откройте «Безопасность» → «Перенос на другой компьютер», придумайте отдельный пароль длиной не менее 12 символов и скачайте файл `.wbai`. Он зашифрован AES-256-GCM и содержит отзывы, товары, черновики, правила, историю, профили магазинов и обычные настройки. Загрузите этот файл в свой Google Drive, а пароль сохраните отдельно. Google Таблицы для такой копии не используются: они не подходят для структуры локальной базы и безопасного хранения данных.

На другом компьютере установите и запустите приложение, создайте локальный пароль, скачайте `.wbai` из Google Drive и восстановите его в том же разделе «Безопасность». Пароль и активная сессия нового компьютера сохранятся. WB Token и ключ Tavily намеренно не переносятся: они защищены Windows DPAPI и должны быть введены заново. После восстановления приложение автоматически включает SAFE MODE и TEST MODE, чтобы данные нельзя было случайно отправить в Wildberries.

`restore.bat имя.db` останавливает приложение, проверяет integrity и восстанавливает выбранную локальную копию. Затем создайте новый пароль и подключите токен заново. Включаются SAFE MODE и TEST MODE. Перед восстановлением создайте копию текущего состояния.

`update.bat` останавливает приложение, устанавливает зависимости из lock-файлов, пересобирает интерфейс и применяет миграции. Новые исходники нужно предварительно получить из доверенного источника; скрипт не делает автоматический git pull и не перезаписывает локальные правки.

## Проверки

`test.bat` запускает backend-тесты на отдельной временной БД. В frontend: `pnpm run typecheck`, `pnpm run build`. Тесты WB используют HTTP mock, не токен владельца. Состояние фактически выполненной проверки записано в `VERIFICATION.md`.

Перед сохранением черновика выполняется автоматическая проверка качества: связь с отзывом, конкретика, эмпатия, обязательное действие для жалобы и запрет отправлять покупателя «писать продавцу». Слабый ответ один раз автоматически переписывается. Оценка и замечания показаны рядом с черновиком. Ручные правки владельца формируют предпочтения активного профиля и учитываются при следующих генерациях.

Проверка качества имеет собственную версию. После изменения правил старые оценки пересчитываются при открытии отчёта, поэтому прежняя отметка не может ошибочно считаться актуальной.

В настройках можно задать отдельный стиль ответов для бренда или категории и включить автоматическую подготовку новых черновиков по расписанию. Дополнительный режим создаёт действие для публикации только для ответов на отзывы 4–5★, прошедших заданный порог качества; отправка в Wildberries всё равно требует подтверждения владельца. Аналитика показывает товары с повторяющимися жалобами и открывает по ним очередь внимания.

Отзывы и товары загружаются страницами и ищутся на сервере. «Очередь» показывает фоновые синхронизации и подготовку автоответов, прогресс, повторы и отмену. Завершённые или отменённые записи о правилах можно удалить из истории «Действия»; само действующее правило удаляется отдельно в «Памяти». В «Настройках» можно включить расписание синхронизации товаров, отзывов и локальных резервных копий; по умолчанию расписание выключено.

Поиск инструкций поддерживает резервный DuckDuckGo и Tavily API. Ключ Tavily шифруется через Windows DPAPI и исключается из резервных копий. Без ключа приложение отмечает недоступность интернет-источника, если DuckDuckGo показывает защиту от автоматических запросов. Найденные в интернете неподтверждённые фрагменты обновляются не реже одного раза в 30 дней.

Ограничения: локальная расшифровка VIN требует ранее подтверждённого профиля; коммерческие каталоги не подключены. Полная формальная защита от всех ошибочных утверждений LLM невозможна: черновики требуют проверки. Планировщик работает, пока приложение запущено; после перезапуска прерванное задание можно повторить из очереди. Локальная Windows-версия является основным вариантом запуска.

## Docker Compose (альтернатива)

Нужен Docker Desktop с Linux-контейнерами. Этот способ требует отдельной установки и не использует уже установленный Windows Ollama. Порты публикуются только на 127.0.0.1; внутренний bind 0.0.0.0 ограничен контейнером. Телеметрия Next отключена. База и модели находятся в named volumes Docker.

Создайте ключ Fernet вне OneDrive: `python -c "from cryptography.fernet import Fernet; from pathlib import Path; import os; p=Path(os.environ['LOCALAPPDATA'])/'WBAIAssistant'/'docker.key'; p.parent.mkdir(parents=True,exist_ok=True); p.open('xb').write(Fernet.generate_key())"`. Используйте Python из установленного окружения проекта. Не перезаписывайте существующий ключ. В PowerShell задайте `$env:WB_DOCKER_SECRET_PATH="$env:LOCALAPPDATA\WBAIAssistant\docker.key"`.

Затем: `docker compose build`, `docker compose run --rm backend python -m alembic upgrade head`, `docker compose run --rm backend python -m app.maintenance setup`, `docker compose up -d`, `docker compose exec ollama ollama pull qwen3:4b`. Остановка: `docker compose down` (не добавляйте `-v`, чтобы сохранить данные). Linux-секреты защищаются Fernet с отдельным read-only Docker secret. DPAPI-токены Windows в контейнер не переносятся. Фактическая проверка Docker отмечена отдельно в VERIFICATION.md.
